# Feature 63: Map/world-graph logic is trapped in `agent.py`, reached into via private access by everything that needs it

**Status:** Open

`agent.py` owns all room-resolution and world-graph logic — `update_graph`,
`_resolve_room_name`, `_canonicalize_room`, `_normalize_room`,
`_short_room_name`, `_strip_narrator_prefix`, `_base_room_name`,
`_known_exits`, `_DIRECTION_NORMALIZE`, `_DISAMBIGUATION_RE`, plus
navigation (`_nav_command`, `get_next_move_to_target`) — as private
(`_`-prefixed), agent-internal helpers. But it is no longer only the agent
that needs this: the `query_map` LLM tool (`agent_tools.py::_impl_query_map`
— the map tool built for the tool-calling loop) reads
`state["world_graph"]` directly, and `scripts/generate_map.py` (the
standalone map-generation tool) reaches straight into `agent._resolve_room_name`
— a private function — and `agent.update_graph` to rebuild a graph from a
saved log with no live agent state at all:

```python
# scripts/generate_map.py
from agent import update_graph, _resolve_room_name
```

Confirmed by grep across the whole repo (excluding tests) for `agent\._`
— every room/graph helper in `agent.py` already has at least one external
caller reaching into it as if it were public:

| Function | External callers (non-test) |
|---|---|
| `_resolve_room_name` | `parse_strategies/base.py`, `scripts/generate_map.py` |
| `_DIRECTION_NORMALIZE` | `parse_strategies/base.py` |
| `_DIRECTIONS` | `parse_strategies/base.py`, `agent_tools.py` |
| `_short_room_name` | `parse_strategies/base.py` |
| `update_graph` (public) | `parse_strategies/base.py`, `app.py`, `scripts/generate_map.py` |

This is the same shape of problem feature 62 already solved once for
parsing (`ParseStrategy`) — a piece of logic informally shared across
modules via reach-around private access, instead of living somewhere with
a real public API. `ui.py::render_graph` is a further consumer of
`state["world_graph"]` for visualization, and any future map-mutation
tool (e.g. "mark a room as visited," "merge two nodes") would need the
same resolution/canonicalization logic `agent.py` already has, privately.

**Proposed fix:** extract map/world-graph logic into its own module (e.g.
`world_graph.py`, naming to match the `parse_strategies`/`ParseStrategy`
convention if a class-based shape ends up making more sense once designed
— e.g. `MapStrategy`), with a public API:
- `resolve_room_name(graph, room_name, exits=None)`
- `update_graph(state, room_name, exits, previous_room, action)`
- `known_exits(graph, node)`
- `canonicalize_room(name)` / `normalize_room(name)`
- `nav_command(state, target, fast=True)` / `get_next_move_to_target(state, target_room)`
- the `DIRECTION_NORMALIZE` mapping and related regex constants

`agent.py`, `agent_tools.py` (the `query_map` tool, and any future
map-mutation tool), `scripts/generate_map.py`, and `ui.py` should all
import from this new module instead of reaching into `agent.py`'s private
names. `agent.py` keeps calling into it too — it just stops being the
sole owner.

**Relationship to feature 59:** feature 59 is the broader, not-yet-designed
umbrella ("split agent.py into reusable library vs. Knight-Orc-bespoke
layers") — this feature is a concrete, scoped-down first slice of it,
following the same successful pattern as feature 62's `ParseStrategy`
extraction, rather than waiting on the full plan.

## How will we know it worked?

- `scripts/generate_map.py` no longer imports a `_`-prefixed name from
  `agent.py` — its `from agent import update_graph, _resolve_room_name`
  becomes `from world_graph import update_graph, resolve_room_name` (or
  equivalent).
- `agent_tools.py`'s `query_map` tool (and any new map-mutation tool)
  imports from the new module rather than duplicating graph-traversal
  logic inline.
- `agent.py`'s `determine_next_action`/`process_agent_step` call through
  the new module's public functions instead of local private ones — a
  `grep -n "^def _resolve_room_name\|^def update_graph"` (etc.) against
  `agent.py` should come back empty.
- Full test suite passes unchanged — this is a pure code-motion refactor,
  no behavior change, so `tests/test_agent.py`'s existing
  `_resolve_room_name`/`update_graph`/`_known_exits` tests should need
  only import-path updates, not new assertions.

**Effort: Medium | Risk: Low** — mechanical extraction of well-tested,
already-isolated functions; the main work is picking the new module's
public names and updating every import site, not changing behavior.

## Implementation plan

This is a pure code-motion refactor — no behavior change, only where the
code lives and what it's called. Written to be self-contained enough to
execute directly from this doc alone.

### 1. New module: a single flat file, `world_graph.py` (repo root)

Not a package (unlike `parse_strategies/`) — there's exactly one
implementation of "how the world graph works," no polymorphism to justify
splitting "room naming" vs "graph mutation" vs "navigation" into separate
files; ~230 lines total moving from `agent.py`.

Layout (mirrors `agent.py`'s existing order, for an easy line-by-line diff):
1. Module docstring (cross-referencing the bug history it owns: 45, 48,
   49, 57, 59, 74, 76, 78).
2. `import re`, `import networkx as nx`, `from game_config import config`.
3. Private regex/const cluster, **unchanged, stay `_`-prefixed** (grep
   confirms zero external references to any of these): `_ARTICLE_RE`,
   `_LEADING_PREP_RE`, `_LEADING_ARTICLE_RE`, `_NARRATOR_PREFIX_RE`,
   `_NARRATOR_PREFIX_OUTSIDE_RE`, `_DISAMBIGUATION_RE`,
   `_MIN_FUZZY_MATCH_CHARS`.
4. Room-name functions, same order, same docstrings verbatim (do not
   reword — they document real bug history): `short_room_name`,
   `_strip_narrator_prefix` (stays private — no external caller),
   `normalize_room`, `canonicalize_room`, `base_room_name`, `known_exits`,
   `resolve_room_name` (signature unchanged: `(graph, room_name, exits=None)`).
5. Direction vocabulary: `DIRECTIONS`, `REVERSE`, `DIRECTION_NORMALIZE`.
6. `update_graph(state, room_name, exits, previous_room, action)` — unchanged body.
7. `get_next_move_to_target(state, target_room)`, `nav_command(state, target, fast=True)`.
8. `mark_edge_futile(state, from_room, direction)`.

No dependency anywhere in this file on `agent.py`, `parse_strategies`, or
`agent_tools.py`.

|---|---|
| `_short_room_name` | `short_room_name` |

| `_canonicalize_room` | `canonicalize_room` |
| `_base_room_name` | `base_room_name` |
| `_known_exits` | `known_exits` |
| `_resolve_room_name` | `resolve_room_name` |
| `_DIRECTIONS` | `DIRECTIONS` |
| `_REVERSE` | `REVERSE` |
| `_DIRECTION_NORMALIZE` | `DIRECTION_NORMALIZE` |
| `_nav_command` | `nav_command` |
| `_mark_edge_futile` | `mark_edge_futile` |
| `update_graph`, `get_next_move_to_target` | unchanged (already public) |

**Important:** none of `resolve_room_name`/`canonicalize_room`/
`normalize_room`/`base_room_name`/`known_exits`/`short_room_name` are
called from `agent.py`'s own *remaining* code (`determine_next_action`,
`process_agent_step`, `_detect_loop`) — only from within the
room-resolution cluster itself, `parse_strategies/base.py`
(`resolve_room_name` only), and `scripts/generate_map.py`/tests. So
`agent.py` only needs to import back: `DIRECTIONS`, `REVERSE`,
`update_graph`, `get_next_move_to_target`, `nav_command`,
`mark_edge_futile`:

```python
# agent.py, new import line (alongside its other project imports)
from world_graph import DIRECTIONS, REVERSE, get_next_move_to_target, mark_edge_futile, nav_command, update_graph
```

Every remaining bare `_DIRECTIONS`/`_REVERSE` reference in `agent.py`
(inside `_detect_loop`, `determine_next_action`, `process_agent_step`)
loses its leading underscore to match. `import re`/`import networkx as nx`
both stay in `agent.py` (still used directly elsewhere — `_SCORE_RE` etc.,
and `determine_next_action`'s own `nx.shortest_path_length` frontier-scoring,
which does not move).

### 3. No backward-compat re-exports — update every call site directly

Per this repo's convention (no back-compat shims/re-exports), `agent.py`
keeps zero re-exports of the moved names.

**Non-test files:**
- **`parse_strategies/base.py`** — add `import world_graph`. Rename its
  `agent._resolve_room_name` / `agent._DIRECTIONS` / `agent.update_graph`
  call sites to `world_graph.X`. Everything else it reaches into on
  `agent` (`_is_hard_failure`, `_is_soft_failure`, `_record_verb_outcome`,
  `_is_creature`, `_is_death`, `_parse_inventory_response`, `_SCORE_RE`)
  stays as `agent.X` — out of scope for this feature (see feature 64).
- **`parse_strategies/deterministic.py`** — add `import world_graph`
  (`import agent` stays — still needed for `_is_hard_failure` etc.). One
  call site: `agent._DIRECTIONS | set(agent._DIRECTION_NORMALIZE)` →
  `world_graph.DIRECTIONS | set(world_graph.DIRECTION_NORMALIZE)`. This is
  computed inside a function body (not module scope) specifically to
  dodge the `agent` circular-import hazard — that hazard is specific to
  `agent.X` lookups, not `world_graph.X` (see §4); update the comment
  there to say so.
- **`agent_tools.py`** — add `import world_graph`. Two call sites in
  `run_tool_calling_step`: `agent._DIRECTIONS` / `agent._mark_edge_futile`
  → `world_graph.DIRECTIONS` / `world_graph.mark_edge_futile`.
  `agent._snapshot_state`/`agent._compute_utility`/`agent._detect_loop`
  stay untouched. `_impl_query_map` is left as-is (§6 below) — its own
  two `agent.X` calls are in a different function (`run_tool_calling_step`)
  from its own graph-reading logic.
- **`scripts/generate_map.py`** — `from agent import update_graph, _resolve_room_name`
  → `from world_graph import update_graph, resolve_room_name`; rename the
  one call site (`_resolve_room_name(...)` → `resolve_room_name(...)`).
- **`app.py`** — split `from agent import process_agent_step, update_graph`
  into `from agent import process_agent_step` + `from world_graph import update_graph`.
  Call site unchanged (same name).
- **`ui.py`** — no change. `render_graph` only reads `state["world_graph"]`
  directly via plain `nx`/pyvis calls, never calls any moved function.

**Test files** — efficient strategy, not ~17 manual edits:
- **`tests/test_agent.py`**: edit the top-level `from agent import (...)`
  block to drop `_mark_edge_futile`/`_nav_command`/`update_graph` (they no
  longer live in `agent`) and add
  `from world_graph import mark_edge_futile, nav_command, update_graph`.
  Then use `Edit` with `replace_all=true` for each of these exact-string
  pairs (each occurs multiple times, always inside test method bodies as
  inline `from agent import X` statements followed by a call site):
  1. `"        from agent import _resolve_room_name"` → `"        from world_graph import resolve_room_name"`
  2. `"_resolve_room_name("` → `"resolve_room_name("`
  3. `"        from agent import _known_exits"` → `"        from world_graph import known_exits"`
  4. `"_known_exits("` → `"known_exits("`
  5. `"_mark_edge_futile("` → `"mark_edge_futile("`
  6. `"_nav_command("` → `"nav_command("`

  Run replacements 1-2 together, then 3-4, then 5, then 6 (each pair's
  import-line replacement first, so its own call-site replacement doesn't
  collide with a not-yet-renamed import line of a different name). ~6
  `Edit` calls total. A few prose comments also mention old private names
  (e.g. `_REVERSE`, `_DIRECTIONS`, `_canonicalize_room`) — update for
  accuracy while touching the file; they carry no test assertions so are
  optional polish, not required for tests to pass.
- **`tests/test_simulations.py`**: split
  `from agent import _base_room_name, _detect_loop, _normalize_room, process_agent_step`
  into `from agent import _detect_loop, process_agent_step` +
  `from world_graph import base_room_name, normalize_room`; rename the
  two call sites (`_base_room_name(` → `base_room_name(`, `_normalize_room(` → `normalize_room(`).
- **`tests/test_parse_strategies.py`** — grep confirms a real (non-comment)
  `agent._DIRECTION_NORMALIZE` usage inside `_assert_case_applied`'s
  direction-normalization helper. Add `import world_graph` (file already
  has `import agent`), rename that usage to
  `world_graph.DIRECTION_NORMALIZE.get(direction, direction)`. **Must not
  be skipped** — every `KNOWN_CASES`-parametrized test in this file
  depends on it; skipping it breaks `test_llm_json_mode_strategy`/
  `test_llm_tool_call_strategy` with an `AttributeError` the moment
  `agent._DIRECTION_NORMALIZE` stops existing.

No other test file (`test_llm_trace.py`, `test_spec_scenarios.py`,
`test_issue10ab.py`) references any moved name.

### 4. Circular-import safety

`world_graph.py`'s only imports are `re`, `networkx`, and
`game_config.config` (itself a leaf — only imports `json`/`re`). None of
the six moving functions touch `agent`, `parse_strategies`, or
`agent_tools` in any form — `world_graph.py` is a true leaf module,
strictly below `agent.py` in the dependency graph (`agent.py` →
`world_graph.py`; `parse_strategies/*.py` → `world_graph.py`;
`agent_tools.py` → `world_graph.py`; nothing points back). The *existing*
circular-import hazard between `agent.py` and `parse_strategies` (resolved
today by deferring every `agent.X` access in `parse_strategies/*.py` to
function-body scope, not module scope) is completely unaffected —
`world_graph` sits beside/below that cycle, not inside it, so
`parse_strategies/base.py` and `parse_strategies/deterministic.py` can
`import world_graph` at module top level with zero risk regardless of
import order.

### 5. `state`-taking signatures: unchanged

`update_graph`, `get_next_move_to_target`, `nav_command`, and
`mark_edge_futile` all keep their exact current `state`-first signatures
— every live caller already has a full `state` dict on hand, and
narrowing to `(graph, ...)` would just push reconstruction work onto every
real call site for zero benefit. `scripts/generate_map.py::rebuild_graph`
already copes today by faking a minimal `state` dict
(`{"world_graph": graph, "current_room": "Unknown Location"}`) — that
cost doesn't change either way; only its import line changes:

```python
from world_graph import update_graph, resolve_room_name
```

### 6. `agent_tools.py::_impl_query_map` — leave as-is

It builds its own `{direction, destination, futile}`-shaped result for
the LLM tool by iterating graph edges directly — a genuinely different
shape than `known_exits`'s bare `frozenset` of direction strings (built
for `resolve_room_name`'s exit-compatibility check, not for reporting to
a tool). Reusing `known_exits` here wouldn't save anything. Only its two
unrelated `agent._DIRECTIONS`/`agent._mark_edge_futile` calls, in the
different function `run_tool_calling_step`, get renamed per §3.

### Implementation order

1. Create `world_graph.py` — copy the listed line ranges from `agent.py`
   verbatim (docstrings intact), renamed per §2.
2. Edit `agent.py`: delete the moved blocks, add the new import line,
   rename remaining bare `DIRECTIONS`/`REVERSE` references.
3. Edit `parse_strategies/base.py`, `parse_strategies/deterministic.py`,
   `agent_tools.py` together.
4. Edit `scripts/generate_map.py` and `app.py`.
5. Run the fast suite (`pytest tests/ -m "not slow and not llm and not cloud" -q`)
   to catch import errors cheaply before touching test files — expect
   failures concentrated in `test_agent.py`/`test_simulations.py`/
   `test_parse_strategies.py`.
6. Edit `tests/test_agent.py`, `tests/test_simulations.py`,
   `tests/test_parse_strategies.py` per §3.
7. Re-run the fast suite — should be fully green, same pass count as before.
8. `ruff check .`.
9. Optionally run `-m cloud`/`-m llm` suites too if credentials are handy.

- `grep -n "^def _resolve_room_name\|^def update_graph\|^def _nav_command\|^def _mark_edge_futile\|^_DIRECTIONS\s*=\|^_REVERSE\s*=\|^_DIRECTION_NORMALIZE\s*=" agent.py` returns nothing.
- `grep -rn "agent\._resolve_room_name\|agent\.update_graph\|agent\._DIRECTIONS\|agent\._DIRECTION_NORMALIZE\|agent\._known_exits\|agent\._nav_command\|agent\._mark_edge_futile\|agent\._normalize_room\|agent\._canonicalize_room\|agent\._base_room_name\|agent\._short_room_name" --include=*.py .` returns nothing anywhere in the repo.
- Full fast test suite passes with the exact same pass count as before —
  every bug-45 maze-disambiguation test and every bug-78 narrator-prefix
  test in `test_agent.py` passes with only import-line changes, no
  assertion changes.
- `tests/test_parse_strategies.py`'s `KNOWN_CASES`-parametrized tests
  still pass — these exercise `apply_parse_result` end-to-end through the
  real `world_graph.resolve_room_name`/`update_graph`, so a subtle
  behavior change would surface as a wrong `current_room` or missing
  `Unknown (...)` placeholder node.
- A short live session (`python scripts/watch_run.py <N>`, a handful of
  steps) produces a world graph indistinguishable from a pre-refactor run.
- `python scripts/generate_map.py logs/<some-existing-run>.json --out <path>`
  reconstructs the same node/edge counts as before.
