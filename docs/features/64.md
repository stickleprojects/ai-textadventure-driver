# Feature 64: Game-response classification helpers are reached into privately from `parse_strategies`

**Status:** Open

Spotted while reviewing `agent.py` for feature 63. `_is_hard_failure`,
`_is_soft_failure`, `_is_scenery_response`, `_is_failure_response`,
`_is_death`, `_is_creature`, `_parse_inventory_response`,
`_split_item_list` are all pure, stateless, config-driven text
classifiers — each just wraps a `config.*_pattern` regex (or a small text
scan) with no dependency on agent state. They live in `agent.py` as
private helpers, but `parse_strategies/base.py` and
`parse_strategies/deterministic.py` already call into several of them
directly (`agent._is_hard_failure`, `agent._is_soft_failure`, etc.) —
confirmed by grep, e.g. `agent._is_hard_failure` has 6 external call
sites, `agent._is_soft_failure` has 5, `agent._is_creature` has 2, plus
one each for `_is_scenery_response`, `_is_death`, `_parse_inventory_response`,
`_short_room_name` — none of them agent-specific, all of them already
de facto shared infrastructure via reach-around private access. Same
underlying smell as feature 63, smaller in scope.

**Proposed fix:** move these into a new shared module (or, since each one
is a thin wrapper around a `game_config.config` pattern the config module
already owns, consider folding them into `game_config.py` itself as
module-level functions living next to the patterns they wrap —
whichever placement comes out of a short design pass). `agent.py`,
`parse_strategies/base.py`, and `parse_strategies/deterministic.py` should
then all import from there instead of `agent.py` owning them privately.

**Related, lower-priority finding — agent-state bookkeeping helpers:**
`_record_verb_outcome`, `_detect_loop`, `_mark_edge_futile`,
`_snapshot_state`, `_compute_utility` show the identical private-reach-around
pattern (`parse_strategies/base.py` and `agent_tools.py` both call several
of these directly — `_record_verb_outcome` has 7 external call sites).
Unlike the classification helpers above, these mutate/inspect the shared
`state` dict directly rather than being pure functions of text, so it's
less clear they need a "strategy" extraction (there's no alternate
implementation need — only one of each exists, and probably only ever
will) — the fix here may just be dropping the leading underscore and
treating them as `agent.py`'s already-correct, intentionally shared public
surface, rather than moving them anywhere. Worth a short design
conversation, not immediate action.

## How will we know it worked?

- `grep -rn "agent\._is_\|agent\._parse_inventory_response\|agent\._split_item_list"`
  across the repo (excluding `agent.py` and `tests/`) returns nothing —
  every remaining caller imports the public name from wherever this logic
  ends up living.
- Full test suite passes unchanged — pure code motion, `game_config`'s own
  pattern-loading/compilation behavior is untouched.

**Effort: Low | Risk: Low** — smaller and more mechanical than
feature 63; mostly a naming/placement decision, not new logic.
