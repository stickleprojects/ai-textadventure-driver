# Feature 70: Runtime LLM provider toggle + connection check

**Status:** Open

Today `LLM_PROVIDER`/`LLM_MODEL`/`LLM_API_KEY`/`LLM_BASE_URL` are module-level
constants in `app.py`, read once from env vars at process start
(`app.py:60-63`). Switching between local (llama.cpp) and cloud
(Anthropic/OpenAI-compatible) means editing `.env`/env vars and
restarting Streamlit — there's no way to toggle providers from the UI.
There's also no way to verify a configured LLM actually works (bad API
key, wrong base URL, network issue) before booting a run and burning
steps against a broken connection — no ping/health-check pattern exists
anywhere in the codebase today.

**Fix:**

1. **Session-state-backed provider/model config.** Add `llm_provider`,
   `llm_model`, `llm_api_key`, `llm_base_url`, `local_model_path`, and
   `connection_check_result` to `init_state()` (`app.py:109-119`), each
   seeded once from the current `os.environ.get(...)` defaults so
   first-load behavior is unchanged. Replace the module-level constant
   block (`app.py:60-63`) — delete it, and immediately after
   `init_state()`/`state = st.session_state.system_state`
   (`app.py:122-123`), reassign `LLM_PROVIDER`/`LLM_MODEL`/`LLM_API_KEY`/
   `LLM_BASE_URL` from the session-state values instead of `os.environ`.
   `LLM_PROVIDER` is read as a bare global (not a parameter) at 6 call
   sites — `_run_step` (`app.py:131`), `_derive_mode` (`app.py:151`), 4
   places inside the sidebar branch (`app.py:174,181,185,189`), and the
   boot handler (`app.py:203`) — all of which execute *after* this
   reassignment in the same script rerun, so this is a zero-signature-change
   fix; no parameter threading needed.

2. **Sidebar provider selectbox**, `key="llm_provider"`,
   `disabled=engine_running` (move the existing `engine_running`
   computation, `app.py:195-196`, to the top of `with st.sidebar:` so
   it's available earlier). Options: `["local", "anthropic", "openai",
   "deepseek"]` plus the current value appended if it's some other
   custom provider string (today `LLM_PROVIDER` is an open string —
   anything besides `"local"`/`"anthropic"` already routes generically
   through `load_openai_tool_llm` as OpenAI-compatible; don't narrow
   that).

3. **Convert the existing model-path/cloud inputs** (`app.py:175,182-184`)
   from `value=...` to `key="local_model_path"`/`key="llm_model"`/
   `key="llm_api_key"`/`key="llm_base_url"`, each `disabled=engine_running`.
   Using `key=` (not used anywhere in this file today for persistence)
   means Streamlit keeps the session-state entry even while its widget
   isn't rendered (e.g. API Key while "local" is selected) — typing a
   value, switching provider, and switching back preserves what was
   typed, unlike today's `value=`-only inputs which reset to the `.env`
   default on every rerun.

4. **Lock all 5 fields while `engine_running`.** Beyond the toggle
   itself, this closes a latent bug: today *none* of
   `model_path`/`cloud_model`/`cloud_key`/`cloud_url` are disabled during
   Auto-Run, so editing them mid-run silently swaps the `llm`/
   `parse_strategy` objects between steps with no warning. Locking them
   alongside the new provider selector fixes this as a natural byproduct.
   (`interpreter_path`/`rom_path` have the same gap but are unrelated to
   `LLM_PROVIDER` — out of scope here.)

5. **`llm.py` — add `ping()` to all four adapter classes**
   (`LocalLLMAdapter`, `CloudLLMAdapter`, `AnthropicToolAdapter`,
   `OpenAIToolAdapter`), consistent return shape `{"ok": bool, "model":
   str, "latency_ms": float, "error": str|None}`:
   - `LocalLLMAdapter`/`CloudLLMAdapter`: reuse `self.__call__` with a
     trivial prompt, wrapped in `time.monotonic()` timing + broad
     `try/except Exception`. `LocalLLMAdapter` needs a new optional
     `model_path=None` constructor param (currently stores only the
     `llama_cpp.Llama` instance) — `load_llm()` (`llm.py:328-335`, the
     only call site) passes it through. `CloudLLMAdapter` already stores
     `self._model` as the model-ID string — no constructor change
     needed.
   - `AnthropicToolAdapter`/`OpenAIToolAdapter` have no bare single-call
     method (only `start_turn(system_prompt, tools, user_message)`,
     requiring a tool schema). Add a small private module-level dummy
     schema (`_PING_TOOL_SCHEMA`, an `"acknowledge"` tool with an empty
     input schema); `ping()` calls
     `self.start_turn("Connection check.", [_PING_TOOL_SCHEMA], "Call acknowledge to confirm.")`
     in the same timing/try-except wrapper. Both adapters force tool use
     (`tool_choice={"type":"any"}` for Anthropic, `"required"` for
     OpenAI), so `ping()` can treat any exception-free response as
     success without hedging on a plain-text reply. `start_turn`
     unconditionally overwrites `self._messages` (not appends) in both
     classes, so calling `ping()` on an `lru_cache`d instance before real
     use leaves no leaked state for the next real `start_turn`.
   - Broad `except Exception` per method — matches this codebase's
     existing style (`extract_knowledge` today has *no* error handling
     around its raw adapter call at all, so this is the first defensive
     wrapper of its kind, not a departure).

6. **"Check Connection" button** in `app.py`, placed after the (now
   locked) provider/model/key inputs, before Boot:
   ```python
   if st.button("Check Connection", use_container_width=True, disabled=engine_running or llm is None):
       st.session_state.connection_check_result = {"provider": LLM_PROVIDER, **llm.ping()}

   _check = st.session_state.connection_check_result
   if _check and _check["provider"] == LLM_PROVIDER:
       if _check["ok"]:
           st.success(f"Connected to `{_check['model']}` in {_check['latency_ms']:.0f} ms")
       else:
           st.error(f"Connection check failed for `{_check['model']}`: {_check['error']}")
   ```
   `disabled=... or llm is None` covers the missing-SDK/failed-local-load
   case (an `st.warning` already explains why, above). Gating the banner
   on `_check["provider"] == LLM_PROVIDER` means switching providers
   auto-hides a stale result with no extra invalidation code. Clear
   `connection_check_result` in the Reset handler (`app.py:230-246`)
   alongside the other resets.

## How will we know it worked?

- Boot with `LLM_PROVIDER=local` in `.env`; sidebar shows "local"
  selected, model-path input, no API Key field. Switch the selectbox to
  "anthropic" (no `.env`/restart) — API Key/Model/Base URL fields appear
  in the same rerun, model-path field disappears.
- Type into "Model", switch to "local", switch back to "anthropic" — the
  typed value is still there (not reset to the `.env` default).
- Click Boot — all 5 provider/model/key fields become visibly disabled;
  click Reset — editable again.
- Click "Check Connection" with a real local model loaded — several-second
  delay (real inference, not instant), then a green success message with
  model name + latency. Point at a bad API key in cloud mode — red error
  with the underlying auth error text, no crash.
- `pytest tests/ -m "not slow and not llm and not cloud" -q` stays green.
- A real cloud "Check Connection" click costs a small amount of real API
  money — confirm with the user before driving that specific path live
  via the `.claude/skills/run-app/` driver, same as features 66-69.

**Effort: Medium | Risk: Low** — additive session-state plumbing and 4
new adapter methods; existing decide-loop/parsing behavior is untouched.
