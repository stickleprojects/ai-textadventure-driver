# Feature 71: Model/provider metadata in run records

**Status:** Open

Nothing today records which LLM provider/model produced a given run.
The user spotted a hallucination in the same run already documented as
bug 80 (`logs/knight_orc_run_20260709_2242.json`): during the
examine/LOOK thrash, the tool-calling model took the putty knife's
description ("rusty and blunt") and invented a nonexistent "sword" to
examine (step 10, `reason`: *"The game just described a rusty, blunt
sword — I should examine it properly."*). This raises the question of
whether model quality is a factor in thrashing generally — but that
correlation can't be checked today since `runs/<run_id>.json` and the
cross-run strategy history have no provider/model field at all.

Depends on feature 70 landing first — this snapshots whichever
provider/model was actually active at Boot, which is only meaningful
once Boot-time values can differ from the `.env` default (i.e. once the
runtime toggle exists).

**Fix:**

1. **Where it enters `state`: at Boot time**, not state-construction time
   (`_make_clean_state()` runs before Boot, while the provider can still
   change). Inside the "Boot Engine" handler (`app.py:198-226`), right
   after `st.session_state.run_id = ...`:
   ```python
   state["llm_provider"] = LLM_PROVIDER
   state["llm_model"] = model_path if LLM_PROVIDER == "local" else cloud_model
   ```
   using the exact locally-scoped variables that built `llm` this rerun.

2. **`scripts/watch_run.py`** — insert right after `state =
   make_initial_state()` (`scripts/watch_run.py:238`):
   ```python
   state["llm_provider"] = LLM_PROVIDER
   state["llm_model"] = (MODEL_PATH if LLM_PROVIDER == "local" else LLM_MODEL) if llm is not None else None
   ```
   `llm`/`LLM_PROVIDER`/`MODEL_PATH`/`LLM_MODEL` are already resolved
   above this point (`scripts/watch_run.py:191-230`); a `None` cloud
   `llm` already causes an early return (startup_error) before this line,
   so `llm is None` here only occurs for the local+deterministic-parse-strategy
   case — recording `None` then is more honest than recording a
   configured-but-unused path.

   **Update `watch_run.py`, not just `app.py`.** The motivating question
   (correlate thrashing with model quality via anomaly analysis) is
   pipeline-wide, and historically most runs fed into
   `detect_anomalies.py`/`architect.py` come from `watch_run.py`, not the
   GUI (feature 66, which made GUI runs visible to that pipeline at all,
   only landed this session). Both callers already share
   `build_run_record` (feature 66) — this is two lines in each caller's
   state-construction point.

3. **`run_evaluator.build_run_record`** (`run_evaluator.py:200-239`) —
   add two `.get()`-read fields to the returned dict (defensive default,
   so old/test state dicts don't `KeyError`): `"llm_provider":
   state.get("llm_provider")`, `"llm_model": state.get("llm_model")`.
   Per-run only, not per-`game_log`-entry — feature 70's locking
   guarantees one provider/model for a run's entire lifetime, so a
   run-level field captures 100% of the signal. Do not touch the
   `game_log` entry dicts in `agent.py:390-404`/`agent_tools.py:425-439`.

4. **`run_evaluator.merge_run_record`** (`run_evaluator.py:242-270`) —
   also copy `llm_provider`/`llm_model` into the `run_history` entry it
   appends (`run_evaluator.py:261-270`), since `run_history` is the
   aggregate, cross-run artifact someone would actually scan to spot a
   "weaker model correlates with more thrash" trend — omitting it there
   would leave the easiest-to-scan structure unable to answer the
   motivating question.

   **⚠️ Breaking test:**
   `tests/test_issue10c.py::TestMergeRunRecord::test_only_summary_fields_in_history`
   (lines 110-119) asserts the literal key set of a `run_history` entry:
   ```python
   assert set(entry.keys()) == {
       "run_id", "outcome", "final_score",
       "locations_discovered", "npcs_discovered", "treasure_discovered",
       "puzzles_discovered", "puzzles_solved",
   }
   ```
   Must add `"llm_provider"`, `"llm_model"` to this set or the fast suite
   breaks immediately.

5. **`schemas/strategy.schema.json`** — not required (`run_history`
   items already have `"additionalProperties": true`), but add
   `llm_provider`/`llm_model` as explicit optional properties (`"type":
   ["string", "null"]`) for documentation parity with every other
   optional metric field already listed there.

## How will we know it worked?

- Boot a GUI run against a cloud provider, run a few steps, open
  `runs/<run_id>.json` — `llm_provider`/`llm_model` populated with what
  was actually active at Boot, not `null`.
- Run `python scripts/watch_run.py 5` headlessly with
  `LLM_PROVIDER=deepseek` — `runs/watch_*.json` also has non-null
  `llm_provider`/`llm_model`.
- Click Reset after a GUI run (or let `watch_run.py` finish) —
  `configs/knight_orc_strategy.json`'s `run_history` gains one entry
  including the new fields.
- Full fast suite green, including the updated
  `test_only_summary_fields_in_history`.

**Effort: Low | Risk: Low** — pure data-plumbing into an existing shared
function; no behavior change to decide loops or parsing.
