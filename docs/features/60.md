# Feature 60: Code-quality review step in `--spec-target`

**Status:** Open

`agent_dev_loop.py --spec-target` (feature 59 phase 1) only gates a scenario
fix on "does it pass tests" — nothing checks whether the fix is good code:
correctness beyond what the fixture happens to exercise, reuse/simplification
opportunities, or whether the fixer actually extended test coverage rather
than just satisfying the one scenario fixture. PR #62 shipped exactly the
kind of mistake this would have caught early (hardcoded "from you" text the
spec never said) — a human caught it in review, but a review step could
surface issues like that before the PR is even opened.

## Design (agreed with user before building)

- **Advisory, not blocking.** Run a review pass and append findings to the
  PR body (new "Code review" section, alongside the existing "Playthrough
  evidence" one) rather than gating PR creation on it. Matches the project's
  existing "dev/merge stays human-gated" principle (see project memory
  `plan_dev_orchestrator`) — an automated reviewer will have false
  positives, and blocking on those would stall genuinely-good fixes waiting
  on human review anyway. Revisit blocking-on-high-severity-only once a few
  runs show the signal is reliable.
- **Reuse `/code-review`, don't build a new reviewer.** That skill already
  covers correctness + reuse/simplification/efficiency at a tunable effort
  level and supports `--fix`. Invoke it against the scenario's diff at a
  fixed effort level right before commit in `run_spec_target`, fold findings
  into the PR body.
- **Test coverage: start with a cheap signal.** Did the fixer's diff touch
  `tests/` at all (not just source)? Only reach for real coverage tooling
  (e.g. `coverage.py`) later if that proves too coarse.

## Not yet decided

- Which effort level to invoke `/code-review` at for an unattended run
  (medium vs. high — tradeoff is thoroughness vs. added Claude API cost/time
  per scenario fix, on top of the fixer + playthrough calls already made).
- Whether findings should also feed back into the same fixer loop (i.e. an
  extra iteration to address high-severity findings before opening the PR)
  or purely land as PR-body text for the human reviewer.

**Effort: Medium (wires an existing skill into an existing script) | Risk: Low (advisory-only, no gating change to begin with)**
