# Feature 68: Agent-state panel is a flat dict, not a structured component

**Status:** Open

The "Dynamic Schema" panel (`app.py`, `col_state`) renders the agent's
believed state as a single flat `st.json` dict (`Location`, `Active Goal`,
`Inventory`, `Spellbook`, plus `Mode`/`Current reasoning` once feature 67
lands), followed by a separate "Unresolved Anomalies" section below it.
As inventory/spellbook grow over a run, a flat dict gets harder to scan,
and the anomalies section feels bolted-on rather than part of the same
"what does the agent currently believe" picture.

**Fix:** replace the flat dict with a tabbed component using
`st.tabs`, grouping the same information (nothing new needs to be
tracked — this is a display reorganization, not new state):

1. **Overview** — `Location`, `Mode`, `Current reasoning`, `Active Goal`
   (the feature-67 fields, kept together since they're the "what/why"
   summary).
2. **Inventory** — `state["inventory"]` as a list (or `st.write`/bulleted
   list rather than a raw JSON array — easier to scan than
   `st.json`'s bracket formatting for a flat list of strings).
3. **Spellbook** — `state["spellbook"]`, same treatment.
4. **Anomalies** — the existing "Unresolved Anomalies" content
   (currently its own `st.subheader` below the dict), moved into this tab
   so the whole believed-state picture lives in one component instead of
   two separately-headed sections.

No change to `state` shape, `_derive_mode`, or any decide-loop code —
this is `app.py` display code only, reorganizing existing reads into
`st.tabs` instead of one `st.json` block plus a trailing section.

## How will we know it worked?

- The dashboard shows one tabbed component (four tabs: Overview,
  Inventory, Spellbook, Anomalies) instead of a flat JSON dict followed
  by a separate "Unresolved Anomalies" heading.
- Switching tabs shows the same underlying values that used to appear in
  the flat dict/section — e.g. after taking an item, the Inventory tab
  reflects it exactly as the old `Inventory` JSON key did; an active
  anomaly shows in the Anomalies tab exactly as it did in the old
  "Unresolved Anomalies" section.
- No behavior change anywhere else — `pytest tests/ -m "not slow and not
  llm and not cloud" -q` stays green (this touches only `app.py` display
  code, which isn't unit-tested directly, but the state-producing code it
  reads from is unchanged).

**Effort: Low | Risk: Low** — pure layout change over already-displayed
fields.
