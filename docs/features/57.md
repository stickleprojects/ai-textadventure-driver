# Feature 57: CI tests for Streamlit UI

**Status:** Open

Add automated tests for the Streamlit web UI so that regressions like bug 61 (UI ignoring `LLM_PROVIDER`) are caught in CI before merge.

**Motivation:** The current CI pipeline covers linting, JSON schema validation, and unit tests for agent logic and LLM extraction. The Streamlit layer (`app.py`, `ui.py`) is completely uncovered — bugs in session state initialisation, sidebar rendering, or LLM provider wiring are only visible by running the app manually.

**Suggested approach:**
- Use [`streamlit.testing.v1`](https://docs.streamlit.io/develop/api-reference/app-testing) (built into Streamlit ≥ 1.28) — no browser or Selenium needed; runs headlessly in pytest
- Key scenarios to cover:
  - App initialises without errors for both `local` and cloud `LLM_PROVIDER` values
  - Sidebar renders the correct fields for each provider mode (model path vs. API key)
  - Session state contains the expected keys after init
  - Auto-run toggle and step counter behave correctly under a mocked `process_agent_step`
- Mock `load_llm`, `load_cloud_llm`, and `start_level9` so tests don't need a real model or game binary
- Add a `ui` pytest marker and include in the main CI test job (no external dependencies needed)

**How will we know it's fixed?**
- `pytest -m ui -v` passes in CI
- Changing `LLM_PROVIDER` in the test fixture causes the correct sidebar fields to appear/disappear
- A deliberate regression (e.g. removing the `LLM_PROVIDER` check in `app.py`) causes at least one test to fail
