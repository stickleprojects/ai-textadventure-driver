# Feature 67: Dashboard doesn't show the agent's believed room/inventory/objective/mode at a glance

**Status:** Open

The "Dynamic Schema" panel (`app.py`, `col_state`) today shows `Location`,
`Active Goal` (or the literal string `"Exploring"` as a fallback),
`Inventory`, and `Spellbook` — a snapshot of raw state, but not "what is
the agent doing right now and why," which is the thing a user watching a
live session actually wants to answer at a glance (is it stuck examining
something, pursuing a goal, or just wandering).

Both decide paths already compute something usable for this, just not
surfaced together:

- **Legacy path** (`agent.py::determine_next_action`) returns a
  `(action, reason)` tuple every step; `process_agent_step` logs `reason`
  into the `game_log` entry (confirmed: `agent.py:393`). Separately,
  `state["active_goal"]`, `state["current_inspection"]`
  (`target`/`sequence`/`step_index`), and `state["uninspected_objects"]`
  already fully describe a discrete "mode" — pursuing a goal, mid-inspection
  on a specific object at a specific verb step, about to start inspecting
  something queued, or plain exploration — nothing needs to be invented,
  only read and formatted.
- **Tool-calling path** (`agent_tools.py`) also logs a `reason` string per
  entry (the model's own free-text justification for that action —
  confirmed in `logs/knight_orc_run_20260709_2242.json`, e.g. `"Always
  examine objects I encounter"`), but has no equivalent structured
  `active_goal`/`current_inspection` state at all (confirmed: zero
  references to either name in `agent_tools.py`) — the model just decides
  fresh every turn with full context. Inventing a synthetic "mode" for
  this path would misrepresent it as more state-machine-driven than it
  actually is; the model's own stated `reason` is the honest, already-available
  signal for "what does it think it's doing," not a derived label.

**Fix:** extend the Dynamic Schema panel with:
1. **`Mode`** — derived from `active_goal`/`current_inspection`/
   `uninspected_objects` for the legacy path (`"Pursuing goal: <solution>
   on <target>"` / `"Inspecting '<target>' (verb: <current step>)"` /
   `"Exploring (N objects queued)"` / `"Exploring"`). For the tool-calling
   path, label it plainly as freeform (e.g. `"Freeform (model decides each
   turn)"`) rather than fabricating a legacy-shaped mode that doesn't
   apply.
2. **`Current reasoning`** — the most recent `game_log` entry's `reason`
   field (present in both paths already), shown regardless of provider —
   this is the actual "what does the LLM think it's doing" answer in the
   tool-calling case, and a useful cross-check against `Mode` in the
   legacy case.

No new state needs to be computed or tracked — every field involved
already exists per-step; this is read-and-display only.

## How will we know it worked?

- **Legacy path (`LLM_PROVIDER=local` or unset)**: step through a
  sequence that includes at least one object inspection and one active
  goal. `Mode` should read `"Inspecting '<object>' (verb: examine)"` (or
  similar) while `current_inspection.target` is set, switch to
  `"Pursuing goal: ..."` once an anomaly resolves into `active_goal`, and
  read `"Exploring"` with no queued objects and no goal. `Current
  reasoning` shows the same string as the corresponding `game_log` entry's
  `reason` field (spot-check against the I-O Terminal panel just above
  it).
- **Tool-calling path (`LLM_PROVIDER=anthropic`/`deepseek`/etc.)**: `Mode`
  always reads the freeform label, never a legacy-shaped string. `Current
  reasoning` updates every step to the model's latest self-reported
  `reason` — reproduce this bug's original scenario (repeated
  `examine putty knife`/`LOOK`) and confirm the panel visibly shows the
  model's own contradictory reasoning ("I need to reorient myself") next
  to an unchanged `Location`, making the thrash visible in the dashboard
  itself rather than only in the exported log.
- No changes to `game_log` entry shape, `active_goal`,
  `current_inspection`, or any decide-loop behavior — this is additive
  UI-only, confirmed by an unchanged `pytest tests/ -m "not slow and not
  llm and not cloud" -q`.

**Effort: Low | Risk: Low** — pure display logic over existing state
fields; no new state, no behavior change.
