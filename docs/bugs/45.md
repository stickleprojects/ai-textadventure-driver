# Bug 45: Maze rooms with non-unique names loop agent

**Status:** ✅ Fixed

Maze rooms with non-unique names cause the world graph to collapse distinct locations into a single node, triggering a loop. Observed in the "alder clump" area — multiple distinct rooms share the same name but have different exits; the agent loops because it thinks it has already visited and explored the single "alder clump" node.

**Root cause:** `update_graph` uses the raw room name as the node ID; `_resolve_room_name` matched purely on normalised display name, so two physically distinct rooms sharing a name always resolved to the same node.

**Fix:** `agent.py`'s `_resolve_room_name(graph, room_name, exits=None)` now takes the current step's exits as an optional third argument, used to disambiguate between candidate nodes that share a display name:

- No `exits` this step (terse response, nothing to disambiguate with) → falls back to name-only matching, same as before this fix.
- A candidate node with no recorded exits yet, or whose recorded exits (via new helper `_known_exits`) overlap the observed set → treated as the same room and reused. This keeps ordinary revisits merged into one node even when the LLM under-reports an exit on a given visit.
- A candidate whose recorded exits are non-empty and **disjoint** from the observed set → treated as a genuinely different physical room reusing the name; a new node is created with a numeric suffix (`"Alder Clump #2"`, `"Alder Clump #3"`, ...) via new helper `_base_room_name` (strips the suffix back off when re-matching against the shared display name).

`process_agent_step` was reordered so the existing "up"/"down" hallucination filter on `extracted["exits"]` runs *before* room resolution, and the same filtered list is passed to both `_resolve_room_name` and `update_graph` — so resolution never disambiguates on stale/unfiltered exits. `scripts/generate_map.py`'s log-replay path threads exits through the same call for consistency when regenerating a map from a saved run.

**Deviation from the original proposal:** the original write-up suggested stripping the disambiguation suffix from the map display label. Decided against it — `ui.py`'s `_display_label` is left unchanged, so `"Alder Clump #2"` stays visible on the rendered map. Hiding it would make two genuinely different rooms show identical text with no visual distinction beyond graph position, which is worse for a human inspecting the map to understand agent behavior.

**Edge cases handled:** LLM returns empty exits this step (falls back to name-only match, doesn't fragment); exits discovered incrementally across visits (subset/overlap merges into the existing node rather than spawning a new one); a third (or later) genuinely distinct room sharing the name gets the next suffix number, not just a binary #1/#2.

## How will we know it worked?

- `tests/test_agent.py::TestNullRoomHandling` — new unit tests cover: disjoint exits on a repeated name create a new suffixed node; a third disjoint visit gets `#3`; overlapping/subset exits merge into the existing node; a node with no recorded exits yet is still treated as the same room; no exits this step falls back to name-only matching (pre-fix behavior preserved — the original article/description-suffix tests at the top of this class still pass unchanged); `_known_exits` splits a compound alias label; and an end-to-end `process_agent_step` case confirming two consecutive disjoint-exit visits leave `current_room` pointing at two distinct nodes.
- `tests/test_simulations.py::test_maze_walk_keeps_repeated_room_name_distinct` — a genuine multi-step simulation: a scripted 5-response maze walk (`tests/simulations/fixtures.py`) is fed through `process_agent_step` in a loop with **real DeepSeek extraction** (not a mocked dict), gated behind `@pytest.mark.llm` (run with `pytest -m llm`, needs `LLM_API_KEY` in `.env`). Asserts at least 2 and at most 3 distinct "Alder Clump"-family nodes end up in the graph, and that `_detect_loop` never fires across the run. Run 3 times against the real API this session — passed every time.
- Behaviorally, on a live run through a maze area with repeated room names: the step log should show the agent continuing to explore (new `Unknown` exits, new rooms) after a second visit to a same-named room, instead of falling back to `look`/re-treading the same room believing it's fully mapped. `configs/knight_orc_rooms.json` (world graph sidecar) should show more than one node for the repeated display name after such a run.
