# Bug 65: agent_dev_loop.py subprocess output invisible until the step finishes

**Status:** Fixed

`_run_analysis`, `_run_tests`, `_run_scenario_test`, and `_run_playthrough`
in `scripts/agent_dev_loop.py` all called `subprocess.run(..., capture_output=True)`
and only printed the captured `stdout`/`stderr` after the subprocess exited.
For a real game/LLM step (`run_and_analyze.py`, `watch_run.py`) that can take
several minutes, this meant the terminal showed nothing at all for the
entire duration — indistinguishable from a hang. Surfaced when running `./run_dev_loop.sh` (no `--spec-target`) to test the
`run_and_analyze.py` state-key fix (PR #65): several minutes with zero
output, no way to tell whether it was progressing or stuck.

**Fix:** new `_stream(cmd, timeout, shell=False)` helper runs the subprocess
via `Popen`, printing each line of combined stdout/stderr as it arrives
(live progress in the terminal) while also accumulating the full text for
callers that need it (`_run_playthrough` parses `"Run ID: ..."` out of it).
The existing hang-detection timeout (added for bug/feature work around
corrupted state — see `docs/JOURNAL.md`) is preserved via a
`threading.Timer` that kills the process after `timeout` seconds
*independent of output* — a genuinely silent infinite loop still gets
caught, not just a slow-but-chatty one. All four call sites (`_run_analysis`,
`_run_tests`, `_run_scenario_test`, `_run_playthrough`) switched to it.

Not changed: `_bash()`, the tool the fixer agent itself calls mid-conversation
— that output feeds back into the Claude tool-use loop as text, not the
terminal, so buffering there is correct as-is.
