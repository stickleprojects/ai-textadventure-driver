# Bug 64: Known-from-prior-run objects never queued for take

**Status:** Fixed

`known_entities` is pre-seeded at session start from the cross-run strategy sidecar (`entity_verb_outcomes` in `configs/knight_orc_strategy.json`), so it accumulates every object name ever seen in *any* prior run. The queueing check in `process_agent_step` was `obj not in state["known_entities"]` — since that membership is permanent across all runs, any object the agent had ever seen before (in this run or a completely different one) silently failed to enter `state["uninspected_objects"]`, so `determine_next_action`'s tier-6 "take X" priority never fired for it. The agent walked past a takeable, un-held item without a single "take" attempt. Nothing about this looks anomalous in a run log (no failure, no repetition), which is why neither the deterministic detectors nor the LLM review flagged it.

A related issue existed in the take-outcome classification: any failure response to `take` (via the broad `_is_failure_response`, matching hard OR soft patterns) was recorded as `"invalid"` and persisted cross-run. A state-dependent failure (e.g. "you're already carrying that") isn't a permanent fact about the object, but would have been blacklisted forever once the agent had the carry-capacity/deferred-verb nuance exercised.

**Fix:**
- `process_agent_step`'s object-queueing gate now checks per-run signals (`state["inventory"]`, `state["uninspected_objects"]`) instead of blanket `known_entities` membership. Only a persisted `verb_outcomes["take"] == "invalid"` (permanently un-takeable, e.g. scenery) blocks re-queueing — that fact is legitimately cross-run.
- The `take` outcome branch now splits `_is_soft_failure` (→ `"blocked"`, never persisted) from `_is_hard_failure` (→ `"invalid"`, persisted), matching the classification already used for every other inspection verb.

Cross-run verb-outcome memory for non-take verbs (skip re-`smell`ing something already known to have no smell) is unchanged — that gating was already correct.
