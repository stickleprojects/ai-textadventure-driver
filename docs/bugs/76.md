# Bug 76: exit hallucination guard only covers up/down, not the rest of the compass

**Status:** Fixed

`agent.py:626-632` (used by both the legacy and tool-calling paths) already
guards against a known over-inference: the LLM reads "Exits lead in all
directions" and expands it to include `up`/`down` even when the response
never actually mentions them, so those two directions are filtered unless
literally present in the response text (case-insensitive). Every other
direction (`north`, `south`, `east`, `west`, `ne`, `nw`, `se`, `sw`, `in`,
`out`) is trusted unconditionally — the same "all directions" idiom over-
infers all of them just as readily as up/down, there's nothing specific
to up/down about the underlying cause. The existing carve-out is narrower
than the problem it was written for.

**Fix:** Generalized the same check to every direction, not just
`up`/`down` — an exit is only kept if the game's response literally
contains it. No new logic, just removing the two-direction special case
from an already-proven check.

**How we know it worked:** a synthetic response containing only
`"Exits lead in all directions."` with no directions individually named
now yields an empty exits list (previously: only `up`/`down` were
stripped, every cardinal/diagonal direction the LLM guessed at would have
passed through).
