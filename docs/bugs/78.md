# Bug 78: A grounded but overly-verbose `room_quote` fragments the world graph

**Status:** Fixed

Observed in a live 6-step run against DeepSeek (`logs/watch_20260709_092710.json`),
while verifying feature 62's parse-strategy refactor. The tool-calling model
correctly satisfied bug 74's grounding requirement (`room_quote` must be a
verbatim substring of the response text) but quoted an entire sentence —
`"You are in a dingy stable"`, `"You are on a jousting field"`, `"You are in
a huge pile of garbage"` — instead of just the room name. Each got persisted
into the world graph as its own distinct node, separate from the existing
canonical short-form entries for the same rooms (e.g. `"huge pile of
garbage"` already exists elsewhere in `configs/knight_orc_rooms.json` from
prior runs). Confirmed this is not new behavior introduced by feature 62's
refactor — `_resolve_room_name`'s article/preposition-stripping
(`agent.py`'s `_ARTICLE_RE`/`_LEADING_PREP_RE`/`_LEADING_ARTICLE_RE`) only
strips a *leading* `"in/on/at" + "a/an/the"`, so it doesn't touch or
recognize `"You are in a dingy stable"` as a match for the same room's
short name — the mechanism is unchanged from the pre-refactor tool-calling
path (`agent_tools.py::_apply_parse_game_response` had the identical
`agent._resolve_room_name(state["world_graph"], room_quote, exits)` call);
this run simply happened to surface it live.

Net effect: every room the model chooses to quote verbosely becomes a
disjoint node from that same room's already-known short-form node — the
same class of problem as bug 45 (maze rooms sharing a display name but not
exits collapsing incorrectly), but the opposite direction: rooms that
*are* the same place splitting into multiple nodes instead of staying
one.

**Reproduced deterministically** in
`tests/test_parse_strategies.py::test_llm_tool_call_strategy_real[room_and_exits-anthropic]`
(was `xfail`, run with `-m cloud`): the real Claude Haiku 4.5 backend,
given `"You are in the dingy stable. Exits lead north and east."`, quoted
`room_quote="You are in the dingy stable"` instead of `"dingy stable"` —
same failure mode, a different model/provider than the original DeepSeek
observation, confirming this isn't provider-specific.

**Fix:**
1. `agent.py` — `_normalize_room`/`_canonicalize_room` now strip a leading
   `"You (go X and) are ..."` narrator preamble (new
   `_strip_narrator_prefix`/`_NARRATOR_PREFIX_RE`/`_NARRATOR_PREFIX_OUTSIDE_RE`),
   mirroring `game_config.py`'s own `room_patterns` two-pattern structure
   (a plain "in/on/at/beside" connector is dropped; "outside"/"inside"
   stay, since — per `_LEADING_PREP_RE`'s existing comment — they denote
   distinct rooms in this game). This alone resolves every case in this
   doc, including the empty-graph (first-visit) case, since it fixes
   `_canonicalize_room` (new-node naming), not just candidate matching.
2. `agent.py` — `_resolve_room_name` also gained a one-directional
   word-set-containment fallback tier (existing node's words ⊆ new
   quote's words, never the reverse — deliberately narrower than "either
   direction" to avoid breaking `test_leading_in_prefix_resolves_to_existing_node`'s
   bare-`"a cave"`-must-not-match-`"inside/outside a cave"` case), with a
   `_MIN_FUZZY_MATCH_CHARS` floor. Found via real data — not just a
   narrator-prefix artifact — that this is genuinely needed:
   `configs/knight_orc_rooms.json` has both `"Headhunters"` and
   `"Headhunters saloon bar of the Orc's Head Inn"` as separate nodes,
   the same physical location the game itself narrates at two levels of
   detail. Fuzzy candidates flow through the same exit-compatibility gate
   as exact matches, so bug 45's maze-room disambiguation is unaffected.
3. `parse_strategies/llm_tool_call.py` — `PARSE_TOOL_SCHEMA`'s
   `room_quote` description now explicitly asks for the shortest grounded
   quote naming the room, with this bug's own example as the anti-pattern.
4. `llm.py` — added a new, separate system-prompt bullet with the same
   guidance (kept separate from the existing "don't shorten the room
   description" bullet so the model doesn't conflate the two rules).
5. `parse_strategies/deterministic.py` needed no change — its
   `room_patterns`-based regex extraction structurally consumes the
   narrator prefix as part of the (non-capturing) match itself, so it
   never produced this bug in the first place.

**Verified**: `tests/test_agent.py` gained 7 new unit tests (direct
repro, empty-graph/first-visit case, outside/inside non-regression, the
"jousting field"/"trampled field" false-merge negative case, the real
`"Headhunters"` case, and two bug-45-non-regression cases).
`tests/test_parse_strategies.py` gained one end-to-end test. Re-ran the
previously-`xfail`'d real test — `test_llm_tool_call_strategy_real[room_and_exits-anthropic]`
now genuinely **passes** against live Claude Haiku 4.5 (along with the
DeepSeek tool-call/JSON-mode/local variants of the same case). Also ran a
fresh 6-step live session against DeepSeek: every extracted room came back
as a clean short form (`"dingy stable"`, `"jousting field"`, `"huge pile
of garbage"`), and the resulting world graph had zero `"you"`-containing
node names.
