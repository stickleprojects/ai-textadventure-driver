# Bug 68: LLM invents a room name for `run to X` responses with no room description

**Status:** Fixed

Found by `scripts/detect_anomalies.py` on a real run
(`logs/watch_20260704_223723.json`): `run to blackthorn ghostwood` and two
similar `run to <room>` commands were flagged as `hallucinated_room_name`
even though the game's response genuinely was _"You are in a blackthorn
ghostwood. Exits lead ..."_ — the LLM extracted the room correctly.

Root cause is in `log_analyzer.py`'s `_is_suspicious_room()`: it treats a
room name as suspicious when it's built entirely from the action's own
object words (originally meant to catch things like a hallucinated "putty
knife room" from action "take putty knife"). But for `run to <room>` /
`go to <room>` commands, the target *is* the room name by construction —
so every successful nav command to a room whose name happens to satisfy
that word-subset check gets flagged, even when the response text
legitimately confirms arrival. The detector had no second check against
the actual response text to tell "name built from the action, and never
appears anywhere in the response" (real hallucination) apart from "name
built from the action, and appears in the response because the action
correctly named the destination" (false positive).

```
"type": "hallucinated_room_name",
"examples": [
  {"action": "run to blackthorn ghostwood", "hallucinated_room": "blackthorn ghostwood",
   "response_snippet": "You are in a blackthorn ghostwood. Exits lead east, south, ..."}
]
```

(That specific example is a false positive of the *old* detector — the room
name *does* appear in the response — which is exactly what the fix
corrects.)

**Fix:** `analyze_log()` in `log_analyzer.py` now also requires that the
suspicious room name actually appear in the step's response text before
flagging it:

```python
if (room and _is_suspicious_room(room, e["action"])
        and room.lower() not in e["response"].lower()):
```

This keeps the detector's original purpose (catching a genuinely invented
room name that never appeared anywhere in the game's own text) while no
longer flagging cases where the LLM correctly read the room out of a
response that does contain it.

**How we know it worked:** `tests/test_log_analyzer.py`'s existing
`hallucinated_room_name` tests continue to pass unchanged — they use
`"Taken."`-style responses that never contain the room name, so the added
check doesn't affect them. `python -m pytest tests/ -x -q
--ignore=tests/test_evals.py` passes (349 passed, 2 xfailed). Behaviorally,
a future anomaly report's `hallucinated_room_name` findings should only
list cases where the named room is genuinely absent from that step's
response text — spot-check a few `example.response_snippet` entries against
`example.hallucinated_room` in the next report that reports this finding.
