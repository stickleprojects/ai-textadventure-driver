# Bug 79: Local-model eval suite failing 7/14 cases, most with a fully empty extraction

**Status:** Open

Ran `./run_evals.sh` (needs the local `EVAL_MODEL_PATH` GGUF, not a cloud
API key — the model happens to be present in this environment) while
verifying feature 62's parse-strategy refactor. `extract_knowledge` itself
was not touched by that refactor (`parse_strategies.LLMJsonModeParseStrategy`
wraps it unchanged), so this is a pre-existing, unrelated finding, not a
regression from that work. 7 of 14 cases failed:

- `horse_is_npc`, `exits_extracted`, `knight_is_npc`, `exits_all_directions`,
  `sub_object_from_examine` — all five failed with `score 0.00`, extraction
  result `{}` (completely empty). `extract_knowledge` returns `{}` when the
  model's output doesn't parse as valid JSON (`llm.py`'s documented
  fallback) — a fully empty result across five different game-output
  shapes suggests the model is failing to produce parseable JSON for these
  cases at all, not just extracting the wrong values.
- `outside_compound_description_is_valid_room` — same `{}` empty-result
  pattern, for a compound room-description case (`"You go north and are
  outside a ...irections and inside."` → expected
  `room: "outside a cave in a juniper scrubland"`).
- `revealed_object_from_take` — the one case that wasn't simply empty:
  action `take mat` on `"Taken. A key was under the mat."` (expects
  `added_to_inventory: ["mat"]`, and `"key"` explicitly forbidden from that
  same field since it was revealed, not taken) returned
  `added_to_inventory: ["mat", "key"]` — the model incorrectly folded the
  newly-revealed object into the inventory-gained list.

Ran against `EVAL_MODEL_PATH` defaulting to
`../models/Phi-3.5-mini-instruct-Q3_K_M.gguf` (the Q3 quantization) with
`EVAL_THRESHOLD=0.7` (both defaults). Not yet checked whether a higher
quantization (`Q4_K_M`/`Q5_K_M`, both also present in `../models/`) does
better on these same cases — worth a first, cheap experiment before
assuming a prompt/schema fix is required, since a 43% JSON-parse-failure
rate is more consistent with a quantization-quality ceiling than with
five independent extraction-schema misses.

**Effort: Medium | Risk: Low** — no production code path is silently
broken by this (the legacy path already tolerates `extract_knowledge`
returning `{}`), but it does mean the local-model path's actual field
extraction reliability is meaningfully worse than these evals are
supposed to guard for, and CI never exercises this suite
(`pytest.ini`'s `-m "not llm"` default), so regressions here go
unnoticed indefinitely.
