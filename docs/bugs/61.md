# Bug 61: llama.cpp GGML assertion crash on model load

**Status:** Open

The Streamlit UI hard-crashes immediately on startup with a `GGML_ASSERT(i1 >= 0 && i1 < ne1) failed` from inside the native llama.cpp tensor library. The process is SIGABRTed by the crash handler before any game content runs.

**Error observed:**
```
/tmp/pip-install-.../llama.cpp/ggml/src/ggml-cpu/ops.cpp:5051:
GGML_ASSERT(i1 >= 0 && i1 < ne1) failed
ptrace: Operation not permitted.
Unable to attach: program terminated with signal SIGABRT, Aborted.
```

**Likely cause:** `llama-cpp-python` was updated (or recompiled) when cloud LLM dependencies were added, and the new version is incompatible with the current model file (`Phi-3.5-mini-instruct-Q3_K_M.gguf`) — either a changed context/batch size assumption or a format version mismatch. The crash path is inside `ggml-cpu/ops.cpp`, which is a tensor dimension bounds check, pointing to a model/library version skew rather than a Python bug.

**To investigate:**
- Check which version of `llama-cpp-python` is installed: `pip show llama-cpp-python`
- Compare against the version that was working before cloud support was added (check `git log` on `requirements.txt`)
- Try pinning back to the previous version
- Alternatively, try the model with `llama-cli` directly to confirm the model file is intact

**How will we know it's fixed?**
- `./run_app.sh` loads the Streamlit UI in the browser without any crash output in the terminal
- The sidebar **Boot Engine** button successfully loads the model (progress bar completes)
- The auto-run loop produces step log entries as before
