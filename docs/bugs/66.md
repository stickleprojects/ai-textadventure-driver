# Bug 66: run_and_analyze.py silent for the whole run (no per-step output, no warning suppression)

**Status:** Fixed

Two related gaps found while testing bug 65's live-streaming fix against
`./run_dev_loop.sh` (no `--spec-target`, the anomaly-based loop, which calls
`scripts/run_and_analyze.py`):

1. **No per-step progress printing at all.** `run_and_analyze.py::run()`'s
   step loop (`for _ in range(steps): process_agent_step(...)`) has no
   `print()` calls in it, unlike `scripts/watch_run.py::run(steps,
   verbose=False)`, which prints a `[i/steps] action | summary` line per
   step when `verbose=True`. Bug 65 fixed `agent_dev_loop.py` so subprocess
   output streams live instead of being buffered — but there's nothing for
   `run_and_analyze.py` to emit in the first place, so a real ~50-step,
   several-minutes-long LLM run is still silent for its entire duration.
2. **Missing Streamlit `ScriptRunContext` warning suppression.**
   `watch_run.py` explicitly suppresses this (harmless, expected when
   `@st.cache_resource`-decorated code in `llm.py` runs outside an actual
   Streamlit session):
   ```python
   logging.getLogger("streamlit.runtime.scriptrunner_utils.script_run_context").setLevel(logging.ERROR)
   ```
   `run_and_analyze.py` doesn't have this, so the warning prints once at
   model-load time. Cosmetic only, but inconsistent with its sibling script.

This is the third time `run_and_analyze.py` has been found out of sync with
`watch_run.py` this session (see also PR #65, missing state keys —
`pending_npc_tasks` etc. — and the wrong graph type). Worth considering, as
a larger follow-up: whether `run_and_analyze.py` should stop maintaining a
parallel implementation and just call `watch_run.py`'s `run()` directly
(it already accepts `verbose`) instead of re-deriving its own initial state
and step loop — not decided, flagging as an option rather than doing it as
part of this fix.

**Fix (minimal, matching bug 65's scope):**
- Added the same `logging.getLogger(...).setLevel(logging.ERROR)` line to
  `run_and_analyze.py`.
- Added a `verbose=True` flag to `run_and_analyze.py::run()` printing a
  `[i/steps] action  room  [elapsed Ns]` line per step, mirroring
  `watch_run.py`'s per-step print (without its ETA calculation, to keep the
  diff small) — real-time progress now has something to stream, on top of
  bug 65 letting it through live.
- Verified with a real 2-step run: no warning noise, live per-step lines
  with elapsed time. Also surfaced that each step took 40–75s on local CPU
  inference — a large part of why a 50-step run felt silent for minutes is
  simply LLM speed, not a tooling gap; not something to fix here.
