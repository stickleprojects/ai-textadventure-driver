# Bug 75: `inventory_changes` has no hard-failure suppression — bug 35 recurring in the new tool-calling path

**Status:** Fixed

Bug 35 ("LLM hallucinates inventory on hard-failure responses") is this
exact failure mode for the *legacy* path: the model claims an item was
added when the response actually says the action failed. The legacy
path's fix (`agent.py:699-702`, still in place, unaffected by this bug)
suppresses `added_to_inventory` entirely whenever the response is a hard
failure.

That suppression was never ported to the new tool-calling path.
`agent_tools.py::_apply_parse_game_response` applies every
`inventory_changes` entry the model reports unconditionally — a
hallucinated `"gained"` on a response that's actually a hard failure (e.g.
`"You can't take that."`) would silently add a fictional item straight
into `state["inventory"]`, which then feeds back into the ambient
"you are currently holding" context shown to the model every subsequent
turn. Not yet caught live (no confirmed occurrence in a saved log at
filing time), but the mechanism is unguarded and the precedent (bug 35)
shows models do this in exactly this game.

**Fix:** `_apply_parse_game_response` now drops any `inventory_changes`
entry with `change: "gained"` when `agent._is_hard_failure(response_text)`
is true, mirroring the legacy path's exact suppression — reusing the same
classification function, not a new heuristic. `"lost"` entries are
unaffected (a hard failure of the just-attempted action doesn't preclude
an unrelated theft narrated in the same response).

**How we know it worked:** a synthetic `inventory_changes: [{"item": "sword",
"change": "gained"}]` paired with a hard-failure response text (e.g.
`"You can't take that."`) no longer adds `"sword"` to
`state["inventory"]`.
