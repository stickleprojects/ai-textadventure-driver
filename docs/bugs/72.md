# Bug 72: `_parse_inventory_response` never matched Knight Orc's real INVENTORY response — `recheck_inventory` silently never resynced

**Status:** Fixed

Discovered while validating the new tool-calling main loop (`agent_tools.py`)
against a live run: the model ran `inventory` to verify its holdings (per
"Handling uncertainty" in `docs/agent_behavior_spec.md`), got back `"You own
a putty knife and a hooded cloak."`, and `state["inventory"]` stayed `[]`
anyway — the exact ground-truth resync the response was supposed to trigger
silently didn't happen.

Root cause is in shared code (`agent.py::_parse_inventory_response`), not
the new module: `_CARRYING_RE` only matches `"carrying[:\s]+..."` phrasing.
Checked every historical run log with an `inventory` action —
`logs/watch_20260701_*.json` through `logs/watch_20260704_*.json` — and
Knight Orc's real response is consistently `"You own X[. You are wearing
Y]."`. `"carrying"` never once appears. This means the **legacy path's own
`recheck_inventory` mechanism** (agent.py:755-765, triggered after a death
or an unrecognized `take` response) has silently never resynced `state`
against ground truth either, for this entire project's history — it just
happened not to surface as a visible bug before because nothing was
watching for the specific symptom (state silently staying stale rather
than erroring).

**Fix:** Added `_OWN_RE`/`_WEARING_RE` patterns for the confirmed real
phrasing, tried first (a positive match takes precedence over the existing
broad `"nothing"` scan in `_NOT_CARRYING_RE`, which risks a false trigger
from unrelated trailing narration — e.g. an NPC's shouted line containing
the word "nothing"). `"carrying"` support is kept as a fallback for other
games/configs that might phrase it that way; existing behavior for it is
unchanged (all three original tests still pass unmodified).

**How we know it worked:** `tests/test_agent.py` —
`test_parse_inventory_response_knight_orc_own_phrasing`,
`test_parse_inventory_response_knight_orc_own_and_wearing`,
`test_parse_inventory_response_own_ignores_trailing_narration` (new), plus
the three original tests unchanged and passing. Live-verified: a fresh
tool-calling-path run where the model took two items then ran `inventory`
to check now shows `state["inventory"]` correctly populated from the real
response instead of staying empty.
