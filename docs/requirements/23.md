# Requirement 23: No detection of NPC inventory transfers

**Status:** Fixed

The LLM extraction schema cannot detect inventory transfers initiated by NPCs — items given by an NPC are not added to inventory, and items stolen are not removed. Both corrupt agent state silently.

**Proposed schema additions:**
- `received_from_npc: [{"item": "spear", "npc": "Denzyl"}]` — item enters inventory via NPC
- `taken_by_npc: [{"item": "gold plate", "npc": "troll"}]` — item leaves inventory involuntarily; agent removes from `inventory`, optionally adds anomaly

**Dependency on requirement 20:** implement that first, then add the hint "NPCs will steal treasure from you if they see you carrying it — put it inside a sack or box" via the hint mechanism.

**Effort: Low | Risk: Low** — schema addition + inventory mutation in `process_agent_step`.

**Reliability note:** unlike hard failure patterns (fixed engine templates), NPC theft/gift dialogue is author-written natural language ("That's mine! He takes the cask", "snatches it from you", "grabs the X back"). This is an extraction schema problem, not a pattern list — the LLM is the right tool but expect ~80% recall with good few-shot examples. Miss rate means inventory will still occasionally drift; not a blocker but worth noting before scoping the work.

**Observed in watch_20260702_124917 step 86:** innkeeper took the cask at step 86 without the agent tracking the inventory loss.

**Fix:** Implemented exactly as proposed above.
- `llm.py`'s extraction schema/prompt now includes `received_from_npc` and
  `taken_by_npc`, with rules and one worked example each, plus both added to
  the list-type normalization in `extract_knowledge()`.
- `process_agent_step` (agent.py) adds `received_from_npc` items to
  `inventory`/`known_entities` (status `"held"`) the same way
  `added_to_inventory` does, and removes `taken_by_npc` items from
  `inventory`. Placed right next to the existing regex-based
  `theft_patterns` loop — this **complements** it rather than replacing it:
  `theft_patterns` reliably catches known fixed phrasings, the new LLM field
  catches the author-written variety a pattern list can't enumerate (per
  the reliability note above), and it's the only mechanism for the gift
  direction at all. Removing an already-removed item is a harmless no-op,
  so overlap between the two isn't a concern.
- No anomaly is added on theft (matches `theft_patterns`' existing
  behavior) — kept minimal per the "optionally adds anomaly" wording in the
  original proposal.
- Added the suggested hint to `configs/knight_orc.json`'s `hints` array
  now that requirement 20 (hints mechanism) is done: "NPCs will steal
  treasure from you if they see you carrying it — put it inside a sack or
  box."

**How we know it worked:** `tests/test_agent.py::TestNpcInventoryTransfers`
(4 tests) — gift adds to inventory and marks `known_entities` status
`"held"`, doesn't duplicate an already-held item, theft removes the item
without touching the rest of inventory, and theft of an item not currently
held is a no-op. `python -m pytest tests/ -q --ignore=tests/test_evals.py`
— 361 passed, 2 xfailed. Behaviorally: a future run where an NPC gives or
takes an item should show `received_from_npc`/`taken_by_npc` in that
step's `extracted` field in the log, and `inventory` (visible via the
`inventory` command or the run's final state) should reflect the change
immediately — not drift silently as in the `watch_20260702_124917`
observation above. The reliability note's ~80% recall caveat still
applies — this doesn't guarantee catching every phrasing, only that a
mechanism now exists where none did before.
