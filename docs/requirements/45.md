# Requirement 45: Agent doesn't interrupt current activity for urgent in-game events

**Status:** In progress — captured as a known gap during feature 62's parse-strategy refactor; not yet designed or implemented.

Both decide paths commit to a plan and keep executing it regardless of
whether the game's own responses, in the meantime, made that plan stale
or dangerous:

- **Legacy path:** `current_inspection` runs a fixed multi-step verb
  sequence (examine → take → read, etc.) against a target object.
  `apply_parse_result`/`process_agent_step` already detects theft
  (`config.theft_patterns`, `taken_by_npc`) and correctly removes a stolen
  item from `state["inventory"]` — but nothing checks whether the object
  `current_inspection` is still mid-sequence on is the one an NPC just
  picked up or stole. The agent will keep issuing `take <object>` /
  `read <object>` against something that's no longer there.
- **Both paths:** there is no combat/attack detection at all today — no
  `config.combat_patterns`-equivalent to `hard_failure_pattern`/
  `soft_failure_pattern`, and no decide-tier (legacy priority list or
  tool-calling) that recognizes "an NPC just attacked you" as an event
  that should preempt whatever inspection/goal/tool-call was already in
  flight. The correct response — fight back, flee, or otherwise react —
  has no mechanism to fire at all; the agent would carry on with its
  current inspection sequence or exploration plan through an attack.

**Relationship to other requirements:** requirement 21 (timed multi-step
NPC strategies) is the proactive counterpart — noticing an opportunity and
acting on it across turns. This is the reactive counterpart — noticing
that the world changed in a way that invalidates what's already in
progress and abandoning/adapting it, not just noticing a new opportunity.
Requirement 40 (NPC-initiated dialogue) is a narrower instance of the same
general gap (an NPC-initiated event with no interrupt path), scoped to
conversation rather than theft/combat.

**New capabilities required:**
- A per-step "does this response demand an immediate reaction" check,
  evaluated regardless of what `current_inspection`/`active_goal` (legacy)
  or the tool-calling model was already doing.
- Combat/attack response patterns (config-driven, matching how
  `hard_failure_pattern`/`soft_failure_pattern` already externalize
  game-specific phrasing rather than hardcoding it).
- Abort/resume semantics for `current_inspection`: if the in-progress
  target is stolen or destroyed mid-sequence, drop it the same way a
  scenery response already aborts inspection (bug 31/70's precedent), but
  triggered by the theft/loss event rather than a failed `take`.
- For the tool-calling path: no structural change needed beyond making
  `notable_events`/the ambient ground-truth context (inventory, current
  room) reflect the interruption promptly — the model already re-decides
  every turn, so the real gap there is combat detection existing at all,
  not an interrupt mechanism on top of a queue.

**Effort: High | Risk: High** — new config-driven pattern category, a new
priority tier ahead of existing ones in `determine_next_action`, and
combat is inherently high-variance/high-consequence to get wrong (misreading
a survivable warning as fatal, or vice versa).
